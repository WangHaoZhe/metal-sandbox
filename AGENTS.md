# Project development conventions

- Use lowercase snake_case for manually maintained files and directories. Preserve the tool-required names `Package.swift`, `Package.resolved`, `AGENTS.md`, `README.md`, and `README_ZH.md`, Icon Composer's `app_icon.icon/Assets`, and application bundle names generated by macOS. This convention does not apply to Swift type names, module names, or existing CLI command names.
- The user-facing desktop application bundle is named `Metal Sandbox.app`; product names are exempt from source-path naming conventions.
- `README.md` and `docs/` are user documentation. Describe usage, supported behavior, and necessary limitations only. Do not include conversation history, test logs, authorization history, test IDs, or machine-specific experiment reports. Store internal acceptance reports in `.verification/` and exclude them from release archives. Put developer testing instructions in `contributing.md`; user documentation must not link to internal acceptance artifacts.

- This project is an **App Sandbox alpha for trusted local development under the same UID**. It does not provide production-grade security guarantees.
- Execute all candidate programs through the management service inside App Sandbox. Administrators choose an allowlist (matches run in parallel; all other tasks run serially) or a denylist (matches run serially; all other tasks run in parallel). Rules cover each entire task and its descendants; they do not detect GPU calls. Do not add a direct-execution fallback that lets Agents bypass the sandbox.
- Keep external correctness checking separate from candidate execution.
- Terminating CPU processes does not prove that GPU work has finished. After confirming process-group cleanup, failed or canceled trusted development tasks, including signal termination and output-limit failures, may release execution permits; this is not GPU-drain certification. An idle Host exit affects only its instance. Retain node quarantine when a Host disconnects during execution, cleanup is uncertain, permits or state are corrupted, or stale execution markers remain. A `critical` thermal state pauses tasks that have not obtained a permit and does not clear an existing quarantine.
- Normal development and testing must not create system users, install launchd jobs, change firewall settings, or run services as root.
- The project's daemon is **metal-sandboxd**. Do not interfere with macOS `/usr/libexec/sandboxd`.
- Build with `swift build` on macOS with Swift 6.0+. Use `swift build --show-bin-path` to locate build products.
- Run unit checks with `.build/debug/sandbox-selftest`. These checks do not depend on XCTest because target Macs may have only Command Line Tools (CLT).
- Run end-to-end tests with `./scripts/test.sh .verification/full`.
- End-to-end tests start and stop their own daemon and deliberately test a crash. Do not run them alongside a management service in use under the same UID.
- Never store SSH passwords or private keys in the repository or deployment scripts.
- `frontend/` is an independent SwiftUI package. All Sandbox operations must use the public CLI. The frontend must not import backend modules or directly access internal sockets, credentials, state files, or container directories.
- Prefer standard SwiftUI/AppKit controls and styles. Use native glass button styles rather than combining a plain button with a glass background. Let native lists handle selection and keyboard interaction. Preserve required AppKit bridges and verified layout and scrolling implementations; do not replace them solely to remove wrappers.
- For frontend checks, use the SDK-specific build command in `contributing.md`, or run `scripts/package_app.py`, followed by `frontend-selftest`. Confirm that the GUI links SDK 26+ and retains macOS 13.0 as its minimum deployment target. Native UI and DMG acceptance must inspect the installed application, not just source build products.
